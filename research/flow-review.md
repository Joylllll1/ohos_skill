| 多个前置条件只记录成一个“等待用户” | 模板按 H1/H2 分列处理者、依赖任务、操作、完成标志、核验和恢复动作；仅解锁已满足的依赖 |
| 换会话后难以找到断点 | 交接必须给出真实记录路径；README 提供包含项目、记录路径、完成条件和任务范围的续接示例 |

| 候选包更新后可能保留旧通过状态 | 源码→包→材料→提交尝试分别绑定，受影响阶段退回 pending/blocked，旧证据留在旧候选历史 |
| 台账全部 pass 仍可能没有真正发布 | 记录用户终点，增加独立发布检查点；区分审核通过、手动/自动/定时发布、平台已发布与商店安装抽查 |
| 审核等待没有具体接续方式 | 保存回执、当前状态、查询入口及下一动作；已审核中即 submission/pass、review/pending；没有后台执行能力时明确交接 |
| 材料整改被写成必需生成新包 | 纯材料改动按平台允许方式复用原包，追加材料修订和提交尝试，不强制重建/升版本 |
| 候选准备可能被未来提交权限不必要地阻塞 | 权限只阻塞确实依赖它的当前操作；发布角色未开通不自动阻塞不需要该角色的构建与材料准备 |
| blocked 状态可没有原因，检查结果也看不到原因 | helper 要求非空 reason，并在每个阶段结果中保留 reason，便于找到交接条目 |

## 场景推演

第一轮独立推演四个场景，发现提交结果未知、多阻塞项、平台审核等待等说明缺口。修订后由另一个独立代理按当前 skill 推演以下五类场景，并复核最后的表述调整。

| 场景输入 | 修订后得到的下一动作与终点 |
|---|---|
| DevEco 登录和镜像下载同时受阻；用户说浏览器已登录、镜像已下载 | 分别核验 IDE 登录及镜像安装启动，不将网页登录或下载完成当作运行条件就绪；保存各自阻塞并继续独立工作 |
| v12 提交点击超时，平台已显示 v12 审核中，本地却已有 v13 | 记录 v12 submission/pass、review/pending，沿用已有请求；v13 独立记录，不擅自替换已授权候选或重复提交 |
| 目标是发布 v7，已获发布授权；审核通过但选择手动发布，helper 无下一阶段 | 继续发布检查点，核对准确版本与已有状态，按授权发布；不因 review/pass 或 next_gate=null 提前停止 |
| 只有介绍文案被退回，二进制未变且平台允许复用 | 修正文案、核对一致性、追加材料修订与提交尝试，复用候选；保留先前回执，重新查询本次结果 |
| 新会话接手；SDK 已解决、发布角色待开通；只需候选包、可用模拟器 | 先读取记录验证 SDK 和模拟器，推进不依赖发布角色的候选准备；仅在当前签名/配置确需该角色时阻塞相应步骤，不强求真机或外部提交 |

复核未发现阻止上述场景继续执行的规则缺口。模拟环境中未实际改变账号、候选包或门户状态。

## 使用时仍需验证的条件

- 宿主实际提供的用户输入/接管/等待接口，以及它能否观察用户登录后的目标工具状态。
- 工程所用 SDK、模拟器/设备、签名环境和平台接口可用性。
- 当前账号的应用权限、素材和审核要求、实际候选和正式发布结果。

准备条件未满足时以具体交接继续推进；不把“文档完整”写成某个实际项目已经全流程完成。

## 接手规则的一致性检查

接手指南分别记录实际进展、证据完整度和下一动作，区分开发版本、候选与发布版本。检查时关注以下通用边界：

- 旧记录与用户更新不一致时，先对齐版本、时间和来源；用户确认不能冒充平台查询。
- 哈希一致只支持同一包的历史验证关联，不能扩展运行环境或声称重新实测。
- 构建环境恢复、源码整合与线上状态分别记录，避免把维护欠项误报为尚未发布。
- inventory 跳过的目录可能含有产物，不能从扫描无结果推断没有证据。
- 缺少平台证据时保留说明，不把 next_gate 当成重复提交指令。

这些是指令与工具职责的一致性检查，不是实际应用或门户的运行验证。
