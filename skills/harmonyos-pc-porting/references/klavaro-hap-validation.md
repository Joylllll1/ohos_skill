# 从原生包到 HAP：Klavaro 的鸿蒙 PC 验收

Klavaro 3.14 是使用 C 和 GTK 的打字练习应用。团队后来确认应用已上架。这里摘录开发期间的两轮模拟器记录，说明如何核对测试包、验证成绩保存，以及把输入问题交给下一位开发者。

## 先确认实际运行的包

2026-11-04，团队用 DevEco 的 Huawei 2in1 模拟器测试调试 HAP，运行环境为 HarmonyOS 6.1.0、API 23、`x86_64`。将 HAP 解包后，比对其中 `x86_64` 的 Klavaro 业务库与同期原生 ZIP，确认内容一致、成绩模块对应提交 `454e3bf`。同时记录了测试 HAP 的 SHA-256。宿主桥接的构建提交在当时的记录里仍待确认。

接手时可以沿着「源码提交 → 对应 ABI 的原生库 → 可安装 HAP → 测试记录」核对。原生 ZIP 能帮助确认业务库来源，实际运行的包需用 HAP 哈希标识。业务库和宿主桥接分别核对来源，换包后按发生变化的部分决定重测范围。

## 用同一安装验证冷启动读回

在这个 HAP 中用模拟器按键事件完成基础、适应性、速度和流畅度四种练习，核对计分和新写入的历史记录。正常关闭 GTK 会话后，终止应用进程，再从同一安装启动。保留原有沙箱，才能检验刚写入的数据能否被新进程读回。

- 进程记录显示旧进程已经结束，新进程使用不同的 PID。
- 四份成绩历史、流畅度综合分、本地榜和配置共七份文件，重启前后 SHA-256 均一致。
- 冷启动后实际打开流畅度进度图和本地榜，两处均显示当轮成绩。其余三个模式的读回证据来自沙箱文件。

这轮结论覆盖 API 23 `x86_64` 模拟器上的该调试 HAP。ARM64 真机结果和商店版本的验收需查阅各自的记录。

## 交接输入问题时保留动作前后的对照

2026-11-05 的单独一轮测试在同类模拟器中复现输入停顿。先在基础课程中确认按键能推动练习，只移动鼠标，再输入下一个字符。练习停在原位置，重新点击输入框再按键也无法推进，重启应用后输入暂时恢复。截图记录了前后状态，宿主日志记录到 XComponent 消费了后续键盘事件。根因在当时尚未确定，复现材料可交给负责宿主输入和 GTK 事件桥接的同学继续排查。

类似问题的交接记录应带上测试包标识、系统/API/ABI、触发动作、预期与实际结果，以及对应的日志或截图。对方拿到修复包后，可以按同样顺序复核键盘在鼠标移动前后是否都能继续推进练习。
