# 签名配置与产物核验

在准备发布签名、签名构建失败或核对候选包时使用。普通编译错误先按发生阶段排查；不要把所有失败都归因于证书。

**文档核对日期：2026-11-25。** 依据华为 [工程级 build-profile.json5](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/ide-hvigor-build-profile-app/) 和 [发布应用](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/ide-publish-app/)。字段及产物行为按实际 DevEco/Hvigor 版本再次确认，不把本地手工签名当作唯一途径。

## 先确认签名步骤是否执行

1. 核对正在构建的工程目录、product、target、build mode 和本次输出目录/时间。IDE 打开的工程、命令行工作副本及旧输出可能不同。
2. 本地签名流程中，检查实际选中的 `app.products[]` 的 `signingConfig` 是否引用 `app.signingConfigs[].name` 中的正确方案。填入证书/Profile/密钥库不等于产品已绑定它；方案名称叫 `release` 也不能证明材料用于发布。
3. 结合本次日志区分：未调度/跳过签名、已执行但失败、成功但取错产物。检查适用的签名任务开关和打包选项；不要为消除错误盲目开启所有开关或重建密钥。
4. 对云签名流程按其实际入口核对账号、应用及平台返回的产物；不要求套用本地密钥库排查步骤。

## 已执行但读取材料失败

核对路径、文件存在性、Profile 用途及应用身份，再区分文件权限、宿主隐私权限、密码解密和证书匹配错误。只输出必要的非敏感检查结果，不打印完整 signingConfigs、密码、密钥或 Profile 正文。

终端能读文件不代表 IDE 或构建守护进程能读。出现 `EPERM` / `EACCES` 时，确认拒绝访问的是哪个进程和目录；若日志指向密钥库旁的 `material` 等工具辅助目录，应检查当前工具的读取约定，而不只检查 `.p12`。这类目录不应凭猜测创建或删除。

确需用户处理时给出具体应用、路径和最小操作：例如在系统设置授予对应目录访问权限，或由用户把密钥库与其必需的辅助文件一起复制到安全、可读的本机私有目录，再更新配置。保留原件，不要求把材料发到聊天、移进公开仓库或放宽为全员可读。用户回复后检查实际文件与引用；仅在需要时重启相关 IDE/守护进程，再重试签名。

## 分别核对 APP、内部模块与测试安装包

- 用当前 SDK 的官方工具验证最终提交 APP，记录其哈希、签名结论、应用身份和分发类型。文件名含 `signed` 或构建显示成功不能代替验签。
- APP 外层签名与内部 HAP/HSP 签名是不同检查对象。当前文档的 `appWithSignedPkg` 选项区分默认 APP 与附带已签名模块的 `all` 产物；不要因为内嵌模块未签名就断言外层 APP 无效，也不要因为外层验签成功就把解出的 HAP 当成可安装包。是否需要该选项由工具版本、分发/安装用途决定，不全局强制开启。
- 目标环境测试使用符合该设备安装条件的 HAP/分发产物，保留测试签名与发布签名的区别。对照发布 APP 中的实际模块清单及业务载荷，核对新增、删除、修改的文件；比较时说明签名元数据等排除项，不能只比较同名文件的交集。
- 载荷一致只支持复用相应业务验证；不能证明商店分发安装、身份权限、升级和数据保留均已验证。将这些结果按实际环境分别记录；签名或产物变化只重开受影响项。

交付明确指出上传哪个文件、哪个可用于安装测试、两者的对应关系及剩余未测项，再按 [发布流程](release.md) 继续。
