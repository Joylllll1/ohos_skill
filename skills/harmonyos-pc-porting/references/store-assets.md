# 商店素材与包内图标

准备应用市场素材时使用本指南；仅本地运行不要求商店素材交付，但修改应用图标时可单独执行“包内图标与启动效果”。先确认应用类型、分发设备、地区和候选版本，再选择规则。素材文件和采集记录保存在目标项目，不放进通用 skill。

## 规格基线

**核对日期：2026-11-23。适用范围：华为应用市场，HarmonyOS 普通应用，PC/2in1。** 下表来自官方 [素材规范](https://developer.huawei.com/consumer/cn/doc/App/agc-help-app-visual-asset-spec-0000002277607976/) 的“应用 → PC/2in1”，是准备材料的基线，不是永久固定值。每次提交前执行本文末尾的复核步骤。

| 商店素材 | 数量 | 像素尺寸 / 比例 | 文件格式与大小 |
|---|---|---|---|
| 应用图标（必传） | 1 张 | 216×216 或 1024×1024；正方形 | PNG；3 MB 以内 |
| 应用介绍截图（必传） | 3–10 张 | 1920×1080；16:9 横向 | PNG、JPG 或 JPEG；每张 5 MB 以内 |

不要把手机、平板等设备的规格套到 PC，也不要从其他设备行继承 WEBP 支持或透明背景要求。官方页面未在普通 PC 应用这一行列出的限制，不自行宣称为平台强制要求。大小按实际文件检查并留余量；若控制台对 MB 的计量或边界有具体校验，以实际规则为准，不靠压到临界值通过。

**商店图标与包内图标分别处理。** 上表用于开发者控制台上传，不代表 HAP 内图标资源、前景/背景分层或启动图标的配置要求。包内图标按目标 SDK 的官方 [应用图标配置](https://developer.huawei.com/consumer/cn/doc/doccenter-feature-dev/bpta-app-icon-configuration/) 和实际资源引用检查；二者品牌一致，但可有不同文件及配置。元服务采用独立规范，不能套本表。

## 准备图标

1. 检查现有应用名称、包内图标及可用源文件，确认本次采用的品牌和素材来源。需要用户决定名称或设计方向时，只交接该决定；不自行替换品牌。
2. 从清晰源文件导出符合当前规格的正方形 PNG。可优先准备 1024×1024，作为制作建议而非唯一允许尺寸；不通过修改扩展名伪装格式，也不把低清图强行放大当作清晰成品。
3. 实际打开导出文件，检查主体完整、边缘清晰、无意外空白/裁切或渲染缺失；在缩略图大小检查可辨认性。这些是质量检查建议，不是新增官方尺寸规则。
4. 比对控制台拟上传图标与安装后应用图标、显示名称。只替换商店图标不代表包内资源已更新；若修改包内图标，重新构建并按影响范围验证候选及相关截图。

缺少图像工具时，可以清点现有素材、写清导出要求并交给用户处理；收到文件后再查尺寸、格式与视觉效果，不能仅凭“导出好了”标为验收通过。

## 包内图标与启动效果

这项与商店素材分别验收。**2026-11-25 核对的官方 [应用图标设计规范](https://developer.huawei.com/consumer/cn/doc/design-guides/application-icon-0000001953444009/) 中，电脑应用图标要求前景、背景双层，各为 1024×1024 正方形 PNG；背景不得包含透明像素，不自行裁圆角或添加透明内边距。** 这是包内应用图标基线，不能反过来覆盖前面的商店上传规格；提交前也需复核。

1. 沿实际应用/入口 Ability 的图标和名称引用检查分层资源及语言、密度等资源变体，避免只改了未被引用的图片。按 [应用图标配置](https://developer.huawei.com/consumer/cn/doc/doccenter-feature-dev/bpta-app-icon-configuration/) 核对资源接入。
2. 检查实际采用的 [启动页配置](https://developer.huawei.com/consumer/cn/doc/harmonyos-Guides/launch-page-config/)：简易启动页使用 `startWindowIcon` / `startWindowBackground`；采用增强启动页时核对生效的 `startWindow` 资源，不能只修改已不生效的简易字段。启动页资源按该方案检查，不强制所有启动资源采用桌面双层形式。
3. 重建后从最终 APP 的实际模块中取出资源检查宽高、格式、背景透明度及引用，留存解包结果。构建过程可能因资源配置改变图片，源图为 1024×1024 不证明包内仍是该尺寸；发现差异先查目标密度和构建配置，不把某个工程的压缩开关当通用修复。
4. 用与候选载荷对应、满足安装条件的包，在目标环境检查桌面、应用中心和窗口图标/名称，并冷启动观察启动页及进入主界面的过程。动态检查可以录屏或连续截帧；未看到启动页不能凭配置写“实测通过”。安装与签名关系见 [签名核验](signing.md)。
5. 覆盖更新后旧快捷方式仍显示旧名称/图标时，区分包内错误与系统缓存，记录旧快捷方式和重新添加后的表现。不能为刷新图标直接卸载含用户数据的应用，也不能用重建快捷方式的结果冒充升级后自动刷新。

没有运行环境时可完成资源与包内容检查，将桌面/冷启动效果单列为待测；不阻塞其他可独立准备的材料。

## 采集应用截图

以下是保证截图真实、清晰、可追溯的工作方法；官方硬性规格以上表和提交时最新页面为准。

1. **绑定候选。** 记录 bundleName、版本、测试安装包路径和 SHA-256，以及测试 HAP 与发布 APP 的对应关系。已有截图先核对版本和界面是否仍适用；不能从文件名相似推断属于当前候选。
2. **列出采集场景。** 在当前数量范围内选择能说明核心任务的不同页面/状态，例如入口、关键操作和结果。先写清每张图要展示什么及顺序，不用重复截图凑数量，也不固定要求五张。不同语言的素材分开记录，按实际提交的本地化配置核对。
3. **准备运行环境。** 使用真实运行的候选应用，在 PC 模拟器或目标设备中进入这些场景；记录系统/API/ABI、设备类型、显示分辨率和缩放。采用非敏感测试数据，关闭无关通知、调试覆盖层和其他窗口，等待页面加载与动画稳定。不能拿设计稿、AI 生成界面或另一个产品的 UI 代替运行截图。
4. **先调整采集区域。** 尽量让应用在接近所需比例和足够像素的区域内正常布局；窗口逻辑尺寸或屏幕看起来是 16:9，不等于导出文件就是 1920×1080。用可用的设备/模拟器截图或窗口捕获工具采集；Web 内嵌应用也应确认画面来自实际宿主，不能把普通浏览器预览冒充目标环境运行。
5. **保留原图，另存提交版。** 记录采集时间、场景、原始路径及导出路径。必要的裁切、等比缩放或格式转换应另存并记录，不能拉伸变形、裁掉关键操作，或拼补不存在的功能。比例/清晰度不合适时优先调整窗口后重拍；不要只改文件名或元数据来凑尺寸。
6. **逐张查看。** 检查文字可读、布局无截断、核心内容完整，无个人账号、私有路径、密钥或无关桌面信息。发现泄露优先更换测试数据重新采集；不通过遮盖错误或合成“正常结果”隐藏实际缺陷。文件属性达标和内容真实分别验收。

没有可用运行环境时，完成场景清单和规格整理，把采集任务按 [交接与恢复](handoffs.md) 交给用户，写明候选、需要打开的页面、导出规格和回传文件位置。只有网页/设计预览时如实标记，不能把“待采集”写成完成。

## 检查文件并形成交付清单

检查的是最终选定上传的文件集，原图、备份和旧版本不计入提交数量。使用可用工具读取真实图像格式、解码后的宽高和字节数，不只看扩展名或窗口尺寸。

macOS 可用以下只读命令检查一个文件；将示例路径替换为实际文件，对图标和每张截图分别执行：

```bash
file /path/to/asset.png
sips -g format -g pixelWidth -g pixelHeight /path/to/asset.png
python3 -c 'import pathlib,sys; print(pathlib.Path(sys.argv[1]).stat().st_size)' /path/to/asset.png
```

其他系统可使用已安装的图像属性工具或解码库，不把 macOS 命令当通用前置依赖。读取失败、文件损坏、实际格式不符、数量不足/超出、尺寸或大小不符时，先明确具体文件和原因，再修正并重查。当前 `porting_helper.py check` 只检查台账及证据完整性，**不检查图像像素、格式、数量或视觉质量**。

在项目 [记录模板](../assets/porting-plan.md#图标与截图清单) 保存：

- 规则来源、适用应用/设备/地区、核对日期及本次材料修订。
- 选定图标和截图的路径、用途/顺序、实际格式、宽高、字节数及 SHA-256。
- 截图所属候选、采集环境与时间、原图到提交版的处理记录。
- 文件属性检查、逐图视觉检查、待补项及下一处理者。

交付时给出明确可打开的素材目录与清单，说明哪些可用、哪些待修。生成或准备文件不等于已上传，上传成功也不等于审核通过。

## 每次提交前复核最新要求

1. 在上传素材、提交审核前重新打开官方 [素材规范](https://developer.huawei.com/consumer/cn/doc/App/agc-help-app-visual-asset-spec-0000002277607976/)，核对目标应用类型与设备对应行，并检查当前控制台素材字段。此检查也适用于被退回后的再次提交；不能直接沿用本指南的核对日期。
2. 在项目记录写下本次实际核对时间、来源及当前数量/尺寸/格式/大小要求。新规则与上述基线不同则采用已确认的新要求，注明差异并重查素材；官方页面与控制台不一致时保留冲突，确认适用范围后再提交。
3. 核对所选包、显示名称、图标、截图和语言是否仍一致；包或界面变化时只重开受影响素材的采集/检查，不把旧图无条件带给新版本。
4. 无法读取最新页面时，可先按标明日期的基线准备文件，但将最新规范核对记为待办。需要用户查看控制台时明确具体位置与待核字段；只暂停依赖该确认的素材上传/提审，其他移植工作继续。
5. 在任务授权范围内上传后，查看平台对文件的校验结果、显示顺序及预览是否正确，记录实际上传的材料修订。保存成功、正式提交审核和最终审核通过分别记录。
